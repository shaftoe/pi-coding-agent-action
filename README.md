# Pi Coding Agent GitHub Action

This is a GitHub action that uses the [pi coding agent](https://pi.dev) to integrate with GitHub workflows (issues, pull requests, etc.).

Inspired by OpenCode's [GitHub action](https://opencode.ai/docs/github/).

## Features

- **Issue assistance**: Type `/pi` in an issue comment to have the agent analyze the issue and create a fix
- **PR assistance**: Type `/pi` in a PR comment to have the agent review and improve the pull request
- **Automated commits**: The agent can make changes, commit them, and create PRs automatically
- **Flexible LLM support**: Support for various providers (Anthropic, OpenAI, Google, and more)

## Usage

### Interactive Workflows

Create a GitHub workflow that triggers on comments or issue events, and use the `if` condition to filter for the trigger phrase:

```yaml
name: Pi AI Agent

on:
  issue_comment:
    types: [created]
  issues:
    types: [opened, edited]

permissions:
  contents: write
  issues: write
  pull-requests: write

jobs:
  pi-agent:
    if: contains(github.event.comment.body, '/pi')
    runs-on: ubuntu-latest

    steps:
      - name: Checkout repository
        uses: actions/checkout@v6
        with:
          fetch-depth: 0

      - uses: actions/setup-node@v6
        with:
          node-version: 24

      - name: Run Pi agent
        uses: shaftoe/pi-coding-agent-action@v2
        with:
          github_token: ${{ secrets.GITHUB_TOKEN }}
          provider: anthropic
          model: claude-sonnet-4-20250514
          token: ${{ secrets.ANTHROPIC_API_KEY }}
          thinking_level: medium
```

### Non-Interactive Workflows

You can use the `prompt` input to run the agent without requiring a comment trigger. This is useful for automated workflows like PR reviews, scheduled tasks, or prompts generated by a previous step:

```yaml
name: Review PR

on:
  pull_request:
    types: [opened, synchronize, reopened]

permissions:
  contents: write
  issues: write
  pull-requests: write

jobs:
  pi-agent:
    runs-on: ubuntu-latest

    steps:
      - name: Checkout repository
        uses: actions/checkout@v6
        with:
          fetch-depth: 1

      - uses: actions/setup-node@v6
        with:
          node-version: 24

      - name: Run Pi agent
        uses: shaftoe/pi-coding-agent-action@v2
        with:
          github_token: ${{ secrets.GITHUB_TOKEN }}
          provider: anthropic
          model: claude-sonnet-4-20250514
          token: ${{ secrets.ANTHROPIC_API_KEY }}
          thinking_level: medium
          prompt: 'Review this pull request for security issues'
```

The prompt can also come from a previous workflow step:

```yaml
      - name: Generate prompt
        id: generate-prompt
        run: |
          echo "prompt=Review the changes in PR #${{ github.event.pull_request.number }}" >> "$GITHUB_OUTPUT"

      - name: Run Pi agent
        uses: shaftoe/pi-coding-agent-action@v2
        with:
          github_token: ${{ secrets.GITHUB_TOKEN }}
          provider: anthropic
          model: claude-sonnet-4-20250514
          token: ${{ secrets.ANTHROPIC_API_KEY }}
          thinking_level: medium
          prompt: ${{ steps.generate-prompt.outputs.prompt }}
```

When using the `prompt` input, the action still enriches the prompt with issue/PR context (title and description) if available in the workflow context.

### Quick Start

Create a workflow file, e.g. `.github/workflows/pi-agent.yml`. See the [interactive](./.github/workflows/pi.yml) and [non-interactive](./.github/workflows/pr.yml) workflows in this repository to get started.

## Inputs

| Input | Description | Required | Default |
|-------|-------------|----------|---------|
| `github_token` | GitHub token for API access | Yes | - |
| `provider` | LLM provider (anthropic, openai, google, etc.) | Yes | - |
| `model` | Model to use (e.g., claude-sonnet-4-20250514, gpt-4o, gemini-2.5-pro) | Yes | - |
| `token` | Provider API token | Yes | - |
| `thinking_level` | Model thinking level (off, low, medium, high) | No | off |
| `trigger` | Trigger phrase to invoke the action | No | /pi |
| `prompt` | Optional prompt to send to the agent (skips comment extraction) | No | - |

## How It Works

1. User comments `/pi [instructions]` in an issue or PR, or a workflow provides a `prompt` input
2. Action enriches the prompt with issue/PR context (title, description, comments)
3. Adds an "eyes" reaction to provide visual feedback
4. Initializes a Pi client session with the specified model and provider
5. Sends the enriched prompt to the agent
6. Agent can use custom tools to:
   - Read and modify files
   - Create pull requests
   - Update existing pull requests
   - Fetch issue/PR thread information
7. If changes are made, the agent uses the `create_pull_request` tool to:
   - Create a new branch: `pi/issue{number}-{timestamp}`
   - Stage all modified files
   - Commit with AI-generated summary
   - Push to remote
   - Create a new PR
8. Action removes the reaction and posts the result as a comment

## Architecture

The action is built on top of the [Pi coding agent](https://pi.dev) framework and consists of several key components:

### Core Components

- **`src/run.ts`** - Main entry point that orchestrates the GitHub workflow integration, manages the agent lifecycle, handles user prompts, and finalizes execution by posting comments
- **`src/pi/`** - Pi client integration layer
  - **`client.ts`** - Pi SDK wrapper that handles model resolution, authentication, session creation, and prompt execution for headless GitHub Actions use
  - **`resource-loader.ts`** - Configures the resource loader with custom tools, logging, and system prompt overrides
  - **`logging.ts`** - Extension factory that provides detailed logging of tool execution and agent session lifecycle
  - **`prompt.ts`** - Central prompt management including system prompt and tool-specific guidelines
  - **`tools/`** - Custom tool definitions that extend Pi's built-in capabilities
- **`src/github/`** - GitHub API interaction layer
  - **`context.ts`** - Context extraction (issue/PR data, comment threads, timing information)
  - **`octokit.ts`** - GitHub client (Octokit) initialization and caching
  - **`reactions.ts`** - Reaction management (add/remove "eyes" reaction)
  - **`comments.ts`** - Comment creation and formatting
  - **`pull-request.ts`** - Pull request creation via GitHub API
  - **`pull-request-update.ts`** - Pull request update functionality
  - **`git-utils.ts`** - Git operations and change detection
  - **`constants.ts`** - Configuration constants

### Custom Tools

The action extends Pi with three internal tools registered via the `ExtensionAPI`:

| Tool | Description |
|------|-------------|
| `create_pull_request` | Creates a new pull request by detecting file changes, creating a branch, committing changes via GitHub API, and opening the PR. Supports `dry_run` mode for testing without actual PR creation. |
| `update_pull_request` | Updates an existing pull request by pushing new commits to the PR branch and optionally updating the title and/or description. Supports `dry_run` mode for testing without actual modifications. |
| `get_issue_or_pr_thread` | Retrieves the full thread of an issue or pull request including title, body, state, labels, branch info (for PRs), and all comments. Useful for understanding the full context before making changes. |

### Data Flow

```
┌─────────────────┐
│ GitHub Event    │ (comment, issue, PR)
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│ run.ts         │ - Extracts prompt & context
│                │ - Initializes Pi client
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│ Pi Client      │ - Loads resources & tools
│ (client.ts)    │ - Runs agent session
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│ Agent + Tools  │ - Reads/writes files
│                │ - Uses GitHub tools
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│ GitHub API     │ - Creates/updates PRs
│ (github/)      │ - Posts comments
└─────────────────┘
```

## Development

### Validation

Before committing, the following checks should be run:

```bash
bun run validate
```

This runs:
- Code formatting (Prettier)
- Linting (ESLint)
- Type checking (TypeScript)

Individual commands:
```bash
bun run format       # Check formatting
bun run format:fix   # Fix formatting issues
bun run lint         # Check linting
bun run lint:fix     # Fix linting issues
bun run type-check   # Type check
bun run test         # Run tests
```

### Building

The action is automatically built via the `prepare` script:

```bash
bun run package
```

This runs the build script which compiles TypeScript to JavaScript in the `dist/` directory.
