# Pi Coding Agent GitHub Action

This is a GitHub action that uses the [pi coding agent](https://pi.dev) to integrate with GitHub workflows (issues, pull requests, etc.).

Inspired by OpenCode's [GitHub action](https://opencode.ai/docs/github/).

## Features

- **Issue assistance**: Type `/pi` in an issue comment to have the agent analyze the issue and create a fix
- **PR assistance**: Type `/pi` in a PR comment to have the agent review and improve the pull request
- **Automated commits**: The agent can make changes, commit them, and create PRs automatically
- **Flexible LLM support**: Support for various providers (Anthropic, OpenAI, Google, ZAI, etc.)

## Usage

### Interactive Workflows

Create a GitHub workflow which triggers when comments are added or issues are opened. The action can be filtered using the `if` condition to only run on specific trigger phrases.

Add `actions/checkout` and `actions/setup-node` as prerequisite steps, then add `shaftoe/pi-coding-agent-action`:

```yaml
name: Pi AI Agent

on:
  issue_comment:
    types: [created]
  issues:
    types: [opened, edited]

permissions:
  contents: write
  issues: write
  pull-requests: write

jobs:
  pi-agent:
    if: contains(github.event.comment.body, '/pi')

    runs-on: ubuntu-latest

    steps:
      - name: Checkout repository
        uses: actions/checkout@v6
        with:
          ref: ${{ github.event_name == 'pull_request' && github.event.pull_request.head.ref || '' }}
          fetch-depth: 0

      - uses: actions/setup-node@v6
        with:
          node-version: 24

      - name: Run Pi agent
        uses: shaftoe/pi-coding-agent-action@v2
        with:
          github_token: ${{ secrets.GITHUB_TOKEN }}
          provider: anthropic
          model: claude-sonnet-4-5
          token: ${{ secrets.ANTHROPIC_API_KEY }}
          thinking_level: medium
```

### Non-Interactive Workflows

You can use the `prompt` input to run the agent without requiring a comment trigger. This is useful for automated workflows like PR reviews, scheduled tasks, or prompts generated by a previous step:

```yaml
name: Review PR

on:
  pull_request:
    types: [opened, synchronize, reopened]

permissions:
  contents: write
  issues: write
  pull-requests: write

jobs:
  pi-agent:
    runs-on: ubuntu-latest

    steps:
      - name: Checkout repository
        uses: actions/checkout@v6
        with:
          fetch-depth: 1

      - uses: actions/setup-node@v6
        with:
          node-version: 24

      - name: Run Pi agent with fixed prompt
        uses: shaftoe/pi-coding-agent-action@v2
        with:
          github_token: ${{ secrets.GITHUB_TOKEN }}
          provider: anthropic
          model: claude-sonnet-4-5
          token: ${{ secrets.ANTHROPIC_API_KEY }}
          prompt: 'Review this pull request for security issues'
```

The prompt can also come from a previous workflow step:

```yaml
- name: Generate prompt
  id: generate-prompt
  run: |
    echo "prompt=Review the changes in PR #${{ github.event.pull_request.number }}" >> "$GITHUB_OUTPUT"

- name: Run Pi agent
  uses: shaftoe/pi-coding-agent-action@v2
  with:
    github_token: ${{ secrets.GITHUB_TOKEN }}
    provider: anthropic
    model: claude-sonnet-4-5
    token: ${{ secrets.ANTHROPIC_API_KEY }}
    prompt: ${{ steps.generate-prompt.outputs.prompt }}
```

When using the `prompt` input, the action still enriches the prompt with issue/PR context (title and description) if available in the workflow context.

### Quick Start

Create a workflow file, e.g. `.github/workflows/pi-agent.yml`. See the [interactive](./.github/workflows/pi.yml) and [non-interactive](./.github/workflows/pr.yml) workflows in this repository to get started.

## Inputs

| Input            | Description                                                             | Required | Default |
| ---------------- | ----------------------------------------------------------------------- | -------- | ------- |
| `github_token`   | GitHub token for API access                                             | Yes      | -       |
| `provider`       | LLM provider (anthropic, openai, google, zai, etc.)                     | Yes      | -       |
| `model`          | Model to use (e.g., claude-sonnet-4-5, gpt-4o, gemini-2.5-pro, glm-4.7) | Yes      | -       |
| `token`          | Provider API token                                                      | Yes      | -       |
| `thinking_level` | Model thinking level (off, low, medium, high)                           | No       | off     |
| `trigger`        | Trigger phrase to invoke the action                                     | No       | /pi     |
| `prompt`         | Optional prompt to send to the agent (skips comment extraction)         | No       | -       |

## How It Works

### Interactive Mode

1. User comments `/pi [instructions]` in an issue or PR
2. Action fetches issue/PR context (title, description, comments)
3. An "eyes" reaction is added to the comment for visual feedback
4. Creates a Pi agent session with model configuration
5. Runs the agent with the enriched prompt (includes context)
6. Posts the result as a comment and removes the reaction
7. If the agent uses the `create_pull_request` tool:
   - A new branch is created: `pi/issue{number}-{timestamp}`
   - Modified files are committed with an AI-generated summary
   - Changes are pushed to remote
   - A new PR is opened

### Non-Interactive Mode

1. Workflow triggers on schedule or specific events
2. The `prompt` input is used directly (no comment extraction)
3. Issue/PR context is still enriched if available
4. Agent processes the prompt and posts results as a comment

## Architecture

The action is built on top of the [Pi coding agent](https://pi.dev) framework and consists of several key components:

### Core Components

- **`run.ts`** - Main entry point that orchestrates the GitHub workflow integration, manages the agent lifecycle, and handles user prompts
- **`index.ts`** - Action entry point that exports the main `run` function

#### Pi Module (`src/pi/`)

- **`client.ts`** - Pi SDK client wrapper that handles model resolution, authentication, agent session creation, and prompt execution
- **`resource-loader.ts`** - Configures the Pi SDK with custom extensions and system prompt overrides
- **`logging.ts`** - Centralized logging using SDK events (`tool_execution_start`, `tool_execution_end`, `before_agent_start`, `agent_end`)
- **`prompt.ts`** - Contains the system prompt and all prompt-related constants (descriptions, guidelines, parameter descriptions) for tool definitions

#### Pi Tools (`src/pi/tools/`)

- **`index.ts`** - Extension factory that registers all custom tools with the Pi agent via the `ExtensionAPI`
- **`create-pr.ts`** - Implementation of the `create_pull_request` tool
- **`update-pr.ts`** - Implementation of the `update_pull_request` tool
- **`get-thread.ts`** - Implementation of the `get_issue_or_pr_thread` tool
- **`common.ts`** - Shared utilities for tool implementations

#### GitHub Module (`src/github/`)

- **`index.ts`** - Barrel export for public GitHub API functions
- **`context.ts`** - Context extraction from GitHub Actions workflow, issue/PR thread retrieval, and prompt enrichment
- **`octokit.ts`** - GitHub client (Octokit) initialization
- **`reactions.ts`** - Reaction management (add/remove reactions for visual feedback)
- **`comments.ts`** - Final comment creation with execution metadata
- **`pull-request.ts`** - Pull request creation logic
- **`pull-request-update.ts`** - Pull request update logic
- **`git-utils.ts`** - Git operations utilities
- **`constants.ts`** - Constants used across the GitHub module

### Custom Tools

The action extends Pi with three internal tools:

| Tool                     | Description                                                                                                                                                                                                                                                                                                               |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `create_pull_request`    | Creates a new pull request by detecting file changes, creating a branch, committing changes via GitHub API, and opening the PR. Automatically determines the default base branch and generates branch names in the format `pi/issue{number}-{timestamp}`. Supports `dry_run` mode for testing without actual PR creation. |
| `update_pull_request`    | Updates an existing pull request by pushing new commits to the PR branch and optionally updating the title and/or description. Supports `dry_run` mode for testing without actual modifications.                                                                                                                          |
| `get_issue_or_pr_thread` | Retrieves the full thread of an issue or pull request including title, body, state, labels, branch info (for PRs), timestamps, and all comments. Useful for understanding the full context before making changes. Does NOT fetch code changes - use read/grep tools for that.                                             |

### System Prompt

The action uses a custom system prompt tailored for GitHub Actions CI/CD environment. Key aspects:

- The agent runs non-interactively and output is sent as GitHub comments
- Focused on code reviews and generating code changes
- Avoids long preambles and focuses on final results
- No footer/metadata is added (automatically appended by the action)
- Project-specific context from `AGENTS.md` is appended to provide additional guidance to the agent

### Logging

Tool execution is logged using Pi SDK events:

- `tool_execution_start` - Logs when a tool is called
- `tool_execution_end` - Logs completion, errors, or cancellation
- `before_agent_start` - Displays agent settings, available tools, system prompt, and user prompt
- `agent_end` - Marks session completion

Tools check `signal?.aborted` directly and return `details.cancelled: true` for cancellations.

## Development

### Prerequisites

- [Bun](https://bun.sh) - Preferred package manager
- Node.js 24+

### Validation

Before committing, the following checks run automatically (via Lefthook):

- Code formatting (Prettier)
- Linting (ESLint)
- Type checking (TypeScript)
- Building

To run all validations manually:

```bash
bun run validate
```

### Testing

The project uses `bun test` for testing:

```bash
# Run tests
bun test

# Run with coverage
bun test --coverage

# Watch mode
bun test --watch
```

### Building

```bash
# Build the action
bun run package

# Or the prepare script (runs package)
bun run prepare
```
