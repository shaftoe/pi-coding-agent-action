# Pi Coding Agent GitHub Action

This is a GitHub action that uses the [pi coding agent](https://pi.dev) to integrate with GitHub workflows (issues, pull requests, etc.).

Inspired by OpenCode's [GitHub action](https://opencode.ai/docs/github/).

## Features

- **Issue assistance**: Type `/pi` in an issue comment to have the agent analyze the issue and create a fix
- **PR assistance**: Type `/pi` in a PR comment to have the agent review and improve the pull request
- **Non-interactive mode**: Use the `prompt` input to run automated workflows without comment triggers
- **Automated commits**: The agent can make changes, commit them, and create PRs automatically
- **Flexible LLM support**: Support for various providers (Anthropic, OpenAI, Google, custom, etc.)

## Usage

### Interactive Workflows

Create a GitHub workflow which triggers when comments are added and filter by `if`:

```yaml
name: Pi AI Agent

on:
  issue_comment:
    types: [created]

permissions:
  contents: write
  issues: write
  pull-requests: write

jobs:
  pi-agent:
    if: contains(github.event.comment.body, '/pi')
    runs-on: ubuntu-latest

    steps:
      - name: Checkout repository
        uses: actions/checkout@v6

      - uses: actions/setup-node@v6
        with:
          node-version: 24

      - name: Run Pi agent
        uses: shaftoe/pi-coding-agent-action@v2
        with:
          github_token: ${{ secrets.GITHUB_TOKEN }}
          provider: anthropic
          model: claude-sonnet-4-5
          token: ${{ secrets.ANTHROPIC_API_KEY }}
          thinking_level: medium
```

### Non-Interactive Workflows

You can use the `prompt` input to run the agent without requiring a comment trigger. This is useful for automated workflows like PR reviews, scheduled tasks, or prompts generated by a previous step:

```yaml
name: Review PR

on:
  pull_request:
    types: [opened, synchronize, reopened]

permissions:
  contents: write
  issues: write
  pull-requests: write

jobs:
  pi-agent:
    runs-on: ubuntu-latest

    steps:
      - name: Checkout repository
        uses: actions/checkout@v6

      - uses: actions/setup-node@v6
        with:
          node-version: 24

      - name: Run Pi agent with fixed prompt
        uses: shaftoe/pi-coding-agent-action@v2
        with:
          github_token: ${{ secrets.GITHUB_TOKEN }}
          provider: anthropic
          model: claude-sonnet-4-5
          token: ${{ secrets.ANTHROPIC_API_KEY }}
          prompt: 'Review this pull request for security issues'
```

The prompt can also come from a previous workflow step:

```yaml
- name: Generate prompt
  id: generate-prompt
  run: |
    echo "prompt=Review the changes in PR #${{ github.event.pull_request.number }}" >> "$GITHUB_OUTPUT"

- name: Run Pi agent
  uses: shaftoe/pi-coding-agent-action@v2
  with:
    github_token: ${{ secrets.GITHUB_TOKEN }}
    provider: anthropic
    model: claude-sonnet-4-5
    token: ${{ secrets.ANTHROPIC_API_KEY }}
    prompt: ${{ steps.generate-prompt.outputs.prompt }}
```

When using the `prompt` input, the action still enriches the prompt with issue/PR context (title and description) if available in the workflow context.

## Inputs

| Input            | Description                                                     | Required | Default |
| ---------------- | --------------------------------------------------------------- | -------- | ------- |
| `github_token`   | GitHub token for API access                                     | Yes      | -       |
| `provider`       | LLM provider (anthropic, openai, google, etc.)                  | Yes      | -       |
| `model`          | Model to use (e.g., claude-sonnet-4-5, gpt-4o, gemini-2.5-pro)  | Yes      | -       |
| `token`          | Provider API token                                              | Yes      | -       |
| `thinking_level` | Model thinking level                                            | No       | off     |
| `trigger`        | Trigger phrase to invoke the action                             | No       | /pi     |
| `prompt`         | Optional prompt to send to the agent (skips comment extraction) | No       | -       |

## How It Works

### Interactive Mode

1. User comments `/pi [instructions]` in an issue or PR
2. Action fetches issue/PR context via GitHub API
3. Adds an "eyes" reaction to indicate processing
4. Creates a new branch: `pi/issue{number}-{timestamp}`
5. Runs Pi agent with the issue context and custom tools
6. If changes are made:
   - Stages all modified files
   - Commits with AI-generated summary
   - Pushes to remote
   - Creates a new PR
7. Posts result as a comment
8. Removes the reaction

### Non-Interactive Mode

1. Workflow triggers on PR open, schedule, or other events
2. Action uses the provided `prompt` input instead of extracting from comments
3. Enriches prompt with issue/PR context if available
4. Same execution flow as interactive mode (steps 3-7)

## Architecture

The action is built on top of the [Pi coding agent](https://pi.dev) framework and consists of several key modules:

### Core Entry Point

- **`src/run.ts`** - Main orchestration logic that:
  - Reads action inputs (provider, model, token, thinking_level)
  - Fetches the user prompt from the triggering GitHub comment or uses the provided prompt
  - Initializes the Pi client session
  - Sends the prompt and handles the streaming response
  - Posts results (or errors) back as GitHub comments
  - Manages reaction lifecycle for visual feedback

### Pi Integration Module (`src/pi/`)

- **`client.ts`** - Pi SDK client wrapper that handles:
  - Model resolution via the ModelRegistry
  - Authentication storage and management
  - Agent session lifecycle (creation, execution, cleanup)
  - Streaming event handling (text deltas and thinking deltas)
  - Headless/non-interactive execution mode

- **`resource-loader.ts`** - Resource loader configuration that:
  - Creates and configures the DefaultResourceLoader
  - Registers custom extension factories (tools and logging)
  - Overrides the default system prompt with a GitHub Actions-tailored one
  - Appends AGENTS.md content to provide project context to the agent

- **`logging.ts`** - Context visualization extension that:
  - Subscribes to SDK events (`tool_execution_start`, `tool_execution_end`)
  - Displays agent configuration before session starts
  - Logs tool execution with status indicators
  - Provides formatted output for GitHub Actions logs

- **`prompt.ts`** - Centralized prompt management containing:
  - System prompt definition for GitHub Actions environment
  - Tool-specific prompts, descriptions, and guidelines
  - Parameter descriptions for tool definitions

### Custom Tools (`src/pi/tools/`)

The action extends Pi with three custom tools registered via the ExtensionAPI pattern:

- **`index.ts`** - Extension factory that registers all custom tools with the Pi agent

- **`create-pr.ts`** - `create_pull_request` tool that:
  - Detects file changes in the working tree
  - Creates a new branch with auto-generated name (`pi/issue{number}-{timestamp}`)
  - Commits changes via GitHub API
  - Creates a new pull request
  - Supports `dry_run` mode for testing

- **`update-pr.ts`** - `update_pull_request` tool that:
  - Detects file changes in the working tree
  - Creates a new commit on an existing PR branch
  - Optionally updates PR title and/or description
  - Supports `dry_run` mode for testing

- **`get-thread.ts`** - `get_issue_or_pr_thread` tool that:
  - Retrieves the full comment thread of an issue or PR
  - Returns title, description, labels, state, author, timestamps
  - For PRs: includes branch names and merge status
  - Useful for understanding context before making changes

### GitHub API Module (`src/github/`)

- **`index.ts`** - Module barrel exports for public API

- **`context.ts`** - Context extraction functions:
  - `getPrompt()` - Extracts user prompt from comment or uses provided input
  - `getIssueOrPRThread()` - Fetches issue/PR thread data
  - `getStartTimeFromContext()` - Extracts workflow start time

- **`reactions.ts`** - Reaction management:
  - `addReaction()` - Adds "eyes" reaction to indicate processing
  - `deleteReaction()` - Removes the reaction when done

- **`comments.ts`** - Comment creation:
  - `createFinalComment()` - Posts the agent's response as a GitHub comment with execution metadata

- **`pull-request.ts`** - PR creation functions:
  - `createPullRequest()` - Creates a new PR via GitHub API
  - Handles branch creation, committing, and PR creation

- **`pull-request-update.ts`** - PR update functions:
  - `updatePullRequest()` - Updates an existing PR via GitHub API
  - Handles committing to existing branch and updating metadata

- **`octokit.ts`** - GitHub client wrapper for API interactions

- **`constants.ts`** - Cancellation messages and shared constants

## Development

### Setup

This project uses [Bun](https://bun.sh) as the package manager.

```bash
bun install
```

### Validation

Before committing, the following checks run automatically (via Lefthook):

- Code formatting (Prettier)
- Linting (ESLint)
- Type checking (TypeScript)
- Tests (bun test)

To run all validations manually:

```bash
bun run validate
```

Individual validation commands:

```bash
bun run format        # Check formatting
bun run format:fix    # Fix formatting issues
bun run lint          # Run ESLint
bun run lint:fix      # Fix ESLint issues
bun run type-check    # Run TypeScript type checking
bun run test          # Run tests
```

### Testing

Run tests with:

```bash
bun test
```

Run tests with coverage:

```bash
bun run test:coverage
```

Watch mode for development:

```bash
bun run test:watch
```

### Building

The action is automatically built during the `prepare` phase:

```bash
bun run prepare
```

Or manually:

```bash
bun run package
```
